# Контракт мобильного клиента и API

[OpenAPI 0.1](openapi.draft.yaml) описывает согласование мобильного клиента с владельцем общего API. Маршруты и состав операций взяты из планов CrustCaper Mobile и Web. JSON-поля, коды ошибок и транспорт гостевой сессии предложены для обсуждения.

Локальный адаптер реализует интерфейс [ShopApi](../src/domain/types.ts) с синтетическими данными. Для интеграции нужны OpenAPI из работающего Spring Boot, механизм выдачи и отзыва гостевой сессии, тестовая точка и разрешённые хосты PSP. После согласования клиент генерируется из закреплённой версии спецификации сервера. Для приложения отдельно согласуются восстановление заказа по контакту, профиль, удаление аккаунта и регистрация push.

При обновлении контракта сервер сохраняет совместимость с предыдущим поддерживаемым мобильным клиентом. Стендовая проверка сравнивает меню, суммы, валюту, слот и раздельные состояния заказа, оплаты и чека. Следует проверить идемпотентное восстановление после потерянного ответа и отказ в доступе к заказу при несовпадении сессии.

Котировка привязана к показанным границам окна самовывоза. При изменении времени клиент получает новое предложение и просит подтверждение. В локальной демонстрации ранее записанные котировки без границ окна истекают, а оформленные заказы восстанавливаются по исходному ключу. При сбое чтения хранилища каталог остаётся доступным для просмотра, оформление блокируется, данные заказов сохраняются в исходном виде.

## Ответы об ошибках

Черновик использует `application/problem+json`. Клиент распознаёт тип ошибки по стабильному URI в `type`. `status` повторяет HTTP-статус, а `code` служит расширением CrustCaper для сопоставления известного типа с внутренним кодом и локализацией. Клиент игнорирует незнакомые расширения. `title` и необязательное `detail` предназначены для чтения. Необязательный `instance` содержит непрозрачный идентификатор случая. [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html)

Черновик предусматривает `400` для неверного ввода, `401` для отсутствующей или недействительной сессии, `404` для недоступного заказа и `409` для конфликта с текущим состоянием. Для чужого и отсутствующего заказа используется одинаковый `404`. Владелец API утверждает URI типов, соответствие кодов и HTTP-статусов. В телах ошибок исключаются телефон, токен, код выдачи и внутренние детали реализации.
