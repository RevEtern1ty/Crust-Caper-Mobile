# Инженерные правила CrustCaper Mobile

Прочитайте [профиль проекта](docs/PROJECT_PROFILE.md) и применимые инструкции каталогов. Перед изменением проверьте состояние рабочей копии, исходный SHA, обычные точки входа и критерии приёмки. Сохраняйте независимые изменения. Для параллельных правок используйте отдельную ветку или worktree.

## Команды из корня репозитория

- `npm ci` устанавливает зависимости из lockfile. Используйте Node.js 24.
- `npm start` запускает Metro, `npm run web` открывает браузерное превью.
- `npm run lint`, `npm run typecheck`, `npm test` проверяют код и поведение. `npm run check` запускает их вместе.
- `npm run build:web` собирает превью. `npm run build:android` и `npm run build:ios` экспортируют JS-пакеты целевых платформ. `npm run android` и `npm run ios` собирают и запускают development build при наличии нативного SDK.
- После `npm run build:web` команда `npm run test:web` прогоняет сценарии через установленный Google Chrome.
- `npm run --silent sbom` выводит SBOM зависимостей в формате CycloneDX.
- [Mobile CI](.github/workflows/mobile.yml) проверяет исходники и зависимости, экспортирует JS, собирает отладочный Android APK и запускает Release-сборку на симуляторе iPhone для pull request, main и ручного запуска. Превью, снимки и SBOM прикрепляются к кандидату. [Порядок приёмки](docs/runbooks/MOBILE_RELEASE.md) содержит матрицу проверок и доказательств.

## Реализация и проверка

- Сохраняйте границы экранов, правил заказа, адаптеров API и хранилищ. Актуальные цены, остатки, слоты, права и платёжный результат подтверждает сервер.
- Для критической записи описывайте идемпотентность, сохранение идентификатора и восстановление после неопределённого ответа. Изменения контракта проверяйте с предыдущим поддерживаемым клиентом при наличии общей версии API.
- Используйте понятные английские имена с единицами измерения. Пишите комментарии на английском для причин решения, инвариантов и внешних контрактов.
- Для каждого критического дефекта подтвердите симптом на исходном SHA. Добавьте сценарий регрессии, который отказывает до исправления и проходит после него. Проверку запускайте из обычных точек входа. Для денег, прав и восстановления проверяйте и исход операции, и сохранённое состояние.
- Для изменений интерфейса проверьте затронутые экраны в EN и RW на ширинах 320, 390 и 430 px, с длинным текстом и увеличенным шрифтом. Проверяйте расположение основных действий, прокрутку, фокус, обратную навигацию и отсутствие перекрытий. Для изменений Web используйте `build:web` и `test:web`. Кандидат на нативный выпуск проходит отдельную проверку устройства по матрице приёмки.
- Используйте синтетические или разрешённые обезличенные данные. Секреты, номера клиентов, токены, коды выдачи и данные оплаты исключайте из диффов, журналов и аналитики. Используйте отдельные права и конфигурацию для каждой среды.

## Ревью и доказательства

- В первую очередь проверяйте деньги, данные, права, совместимость, сбои и восстановление. По каждому существенному замечанию указывайте место, последствие и способ проверки. Критические изменения передавайте на независимое ревью.
- Записывайте SHA рабочего кандидата, среду, сценарий, ожидаемый и наблюдаемый исход, команды и оставшиеся проверки. Для визуального изменения приложите снимки кандидата и результат просмотра. Отдельно фиксируйте браузерный сценарий, экспорт JS, собранный APK, запуск на устройстве и подключённый стенд. Допуск подписанной сборки подтверждает назначенный владелец выпуска.

## Общий Spring Boot API

- Java 21. Из `server/` запустите `./gradlew test bootJar` или `gradlew.bat test bootJar` на Windows. Для интеграционных тестов используйте отдельную локальную PostgreSQL из `server/compose.local.yml`.
- Из корня `npm run build:connected-web` собирает клиент при `CRUSTCAPER_BUILD_PROFILE=local` и `CRUSTCAPER_API_BASE_URL=http://127.0.0.1:18080/api/v1`. `npm run test:connected` проверяет связанный сценарий через локальный сервер.
- Для серверных и клиентских изменений проверяйте OpenAPI, обновление безопасной гостевой сессии, конкурентное бронирование, идемпотентность оплаты и права сотрудника. Среды, подпись и приёмка описаны в [порядке connected-выпуска](docs/runbooks/CONNECTED_RELEASE.md).
