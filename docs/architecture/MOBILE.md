# Архитектура CrustCaper Mobile

## Поток гостевого заказа

Экран меню передаёт позиции и модификаторы в локальную корзину. Оформление проверяет ввод, получает предложение и показывает итог с окном выдачи. Состояние текущего заказа переживает повторное открытие приложения. Экран заказа читает состояние через адаптер; правила цены, слота, доступа и платёжного исхода находятся на серверной стороне контракта.

| --- | --- |
| Маршруты и экран оформления | [app](../../app), [checkout.tsx](../../app/checkout.tsx) |
| Корзина, каталог и язык | [shop.tsx](../../src/state/shop.tsx) |
| Переходы оформления и журнал | [controller.ts](../../src/checkout/controller.ts), [private-storage.ts](../../src/state/private-storage.ts) |
| Прикладной интерфейс и демо-данные | [types.ts](../../src/domain/types.ts), [demo-api.ts](../../src/domain/demo-api.ts) |

Для подключения общий API публикует OpenAPI с версиями, стабильными кодами ошибок и поддерживаемыми версиями клиента. Мобильный план задаёт `GET /api/v1/stores/{id}/menu`, `POST /api/v1/quotes`, `POST /api/v1/orders`, `POST /api/v1/orders/{id}/payments` и `GET /api/v1/orders/{id}`. Клиентские типы и правила интеграции настраиваются по принятому серверному OpenAPI. [Проект контракта](../../contracts/README.md)

Денежные суммы передаются целыми числами в RWF. UTC хранит момент события. Отображение окна выдачи использует `Africa/Kigali`. Если цена, доступность или слот изменились, клиент показывает обновлённое предложение и получает согласие перед записью.

## ADR 001 Локальный адаптер для первого сценария

Клиентский репозиторий начинается с пустой истории. Общий API и учётные данные для тестовой точки на старте не предоставлены. Демонстрационный адаптер позволяет пройти сквозной UI-сценарий и проверить сохранение состояния на синтетических данных. Реализацию сервера и миграции ведёт владелец общей системы. Новый адаптер подключения можно ввести через границу клиента после приёмки OpenAPI, серверной идемпотентности, прав на заказ и тестовых данных. У разработчиков должен остаться локальный режим для воспроизводимых проверок.

Публичные настройки и черновик корзины хранятся в AsyncStorage. Журнал оформления хранит стадию и ключ повторного обращения. В нативной сборке журнал записывается через SecureStore, синтетические заказы — через AsyncStorage. В браузерном превью журнал и заказы хранятся в `sessionStorage` текущей вкладки и восстанавливаются после её перезагрузки. Для вкладки с прежним журналом заказы переносятся из старого браузерного хранилища при первом чтении. Живые контакты и платёжные системы подключаются на стенде.

Для реальной оплаты приложение сохраняет `orderId` и ключ попытки до открытия разрешённого хоста PSP в системном браузере. После возврата и холодного старта статус запрашивается по сохранённому заказу. Параметры ссылки сообщают, какой заказ открыть. Доступ и окончательное состояние оплаты проверяет API. При неоднозначном исходе клиент восстанавливает существующую операцию. Повтор оплаты становится возможен после окончательной сверки и проверки брони сервером.

## Риски и доказательства подключения

| Риск | Контроль и проверка | Ответственный |
| --- | --- | --- |
| Чужой заказ по ссылке | Проверка владельца на API; сценарии с двумя сессиями, отзывом и неподтверждённым контактом. | API |
| Повтор записи при таймауте или двух нажатиях | Ключ намерения и сравнение запроса на сервере, сохранение ID на клиенте. Проверки конкуренции, обрыва после принятия и перезапуска. | API, Mobile |
| Утечка через сборку, логи или push | Разделение сред, проверка SDK и разрешений, защищённое хранилище токенов, общие тексты уведомлений. Проверка конфигурации и фактической сборки. | Mobile, владелец данных |
| Подмена статуса оплаты | Сверка на сервере, системный браузер с разрешённым HTTPS-хостом, ассоциированные ссылки согласованного домена. Проверка задержки, ошибочного возврата и истёкшей брони. | API, Mobile |

## Зависимости и изображения

Для SDK 55 закреплены исправленные версии Zod в Expo CLI и decode-uri-component в цепочке Expo Router. Metro перенаправляет CommonJS-импорт декодера из query-string 7 на совместимый экспорт. При обновлении Router и CLI пересмотреть закрепления и прогнать экспорт всех платформ и навигацию с параметрами.

Инструменты сборки Expo используют `glob` 14.0.3 по схеме [исправления Expo](https://github.com/expo/expo/pull/52819). `@expo/fingerprint` сохраняет прежние версии `glob` и `minimatch` для совместимости хешей проекта и настроек исключения файлов. Проверка исходных карт Web, Android и iOS подтверждает отсутствие этих пакетов в клиентском JS. При обновлении SDK повторите аудит дерева зависимостей, сравните исходные карты и пересмотрите временное закрепление.
